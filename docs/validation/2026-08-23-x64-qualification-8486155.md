## ETW lifecycle

The final 19/19 run proved:

- immediate dashboard smoke exit leaves zero session;
- two live dashboards own distinct Attribution sessions;
- X hides to tray and preserves the live session;
- forced kills leave an orphan, while two relaunch cycles reclaim only the dead owner's session and
  preserve the live peer;
- two real tray Exit operations remove both sessions;
- DNS forced kill/relaunch recovers the orphan and Ctrl+C exits 0 with cleanup;
- forced service termination leaves an Outbound orphan, then configured SCM automatic recovery uses
  a new PID and reclaims it;
- recovered service remains AuditOnly, WFP stays absent, IPC succeeds and HTTPS returns 200;
- final Attribution, DNS and Outbound inventory is empty, no `.NET Runtime` 1026 crash exists, and
  all four protected hashes remain unchanged.

## Harness failures retained as evidence

Earlier red attempts were not discarded. They exposed UI Automation selection mistakes, a French
notification-icon regex that excluded commas, a console-handle loss in the Ctrl+C driver, an
unretained process handle that made `ExitCode` unavailable, a transient `logman` result
`-2147020696`, and a restart race where the SCM recovery action correctly won before `sc start`.

Each was corrected in the external qualification driver without relaxing a product assertion. The
transient `logman` observation also led to a repository change: only that exact error is retried, with
a fixed eight-attempt bound; other failures remain fail-closed.
